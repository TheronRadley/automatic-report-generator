# Contributing

Thanks for your interest in improving Automatic Report Generator.

## Development setup

```bash
git clone https://github.com/TheronRadley/automatic-report-generator.git
cd automatic-report-generator
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev,postgres]"
pytest
```

## Ground rules

- **Correctness first.** Every behaviour change needs tests; bug fixes need a regression test. Run `pytest`, `ruff check src tests examples benchmarks`, and `ruff format --check ...` before opening a PR.
- **No fake functionality.** Documented commands, steps, and options must actually work end-to-end; update `docs/` and `README.md` in the same change when behaviour changes.
- **Security posture is load-bearing.** Do not introduce `eval`/`exec`, string-formatted SQL, unsafe YAML, shell invocation, or unescaped template output. New inputs are untrusted until validated — see docs/security.md.
- **Keep modules focused.** Follow the existing boundaries (adapters in `sources/`, steps in `processing/`, renderers consume `ReportDocument` only). See docs/development.md for "adding things" recipes.
- **Examples stay runnable.** If you change the config schema or a template, regenerate/adjust `examples/` and make sure `reportgen generate examples/configs/sales-report.yaml --all` still works. Example data is synthetic and generated by `examples/generate_demo_data.py` — never commit real data or credentials.
- **Commits:** small, focused, imperative subject lines. Branches: work on a feature branch and open a pull request against `main`; CI (lint, cross-platform tests, build smoke test, audit) must pass.

## Reporting bugs

Include: reportgen version (`reportgen version`), Python version, OS, the command run, the full error output, and — if possible — a minimal report definition plus a few rows of (synthetic or redacted) input data that reproduce the problem.
